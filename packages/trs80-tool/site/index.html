TRS-80 Tool

trs80-tool is a command-line tool for inspecting and manipulating TRS-80 files, cassettes, floppies, and hard disks. Its source code is available on Github.

Installation

You can download stand-alone binaries of the latest version:

  • trs80-tool for Linux
  • trs80-tool for macOS (Apple Silicon)
  • trs80-tool for macOS (Intel)
  • trs80-tool for Windows 10+

On Linux and macOS you’ll need to make the file executable:

% chmod +x trs80-tool

On macOS you’ll additionally have to remove the quarantine:

% xattr -d -r com.apple.quarantine trs80-tool

File formats

The trs80-tool program supports these file formats:

.BAS
Basic program. It’s typically tokenized (token words like PRINT are stored as a single byte), but the tool supports reading Basic programs that are in text (non-tokenized) format. When writing a file with a .BAS extension, the file is always tokenized.
.ASC
Basic program, but always in text (non-tokenized) format. The extension is mostly useful when writing a Basic file, because it tells the converter to use the non-tokenized format.
.WAV
A cassette’s audio stream. It can be at any sampling rate, either 8 or 16 bits per sample, and either mono or stereo.
.CAS
A cassette stored in a compact form where each bit on the cassette is stored as a bit in the file. It includes synchronization headers and bytes, as well as start bits (for high-speed cassettes). This is a decent archival format for cassettes.
.CMD
A machine language program as stored on a floppy disk.
.SYS
The same format as .CMD, but is meant to store system code in a disk operating system. Can also store the boot sector, in which case it’s not in .CMD format, it’s just the raw bytes.
.3BN
A machine language program as stored on a cassette. The name comes from "Model 3 BiNary". This is typically not used, and instead these files are stored within .CAS files.
.L1
A 250-baud file written by a Level 1 machine (Model 1 or 3). It can contain a system file or a Basic program.
.JV1
A floppy disk format for the Model I. It’s very simple, capturing the basic sector data. It does not capture enough information for copy-protected floppies. It’s named after Jeff Vavasour.
.JV3
A floppy disk format for the Model III. It’s very simple, capturing the basic sector data and IDAM structure. It does not capture enough information for copy-protected floppies. It’s slightly more capable than .JV1 because it can encode a mix of FM and MFM signals on the same track.
.DMK
Another floppy disk format, capturing more information from the floppy, such as some bits between sectors. Named after David M. Keil.
.DSK
Generic file extension for floppy disk—could be a .JV1, .JV3, or .DMK file. Use the info command to find out.
.SCP
SuperCard Pro raw flux floppy disk format.
.HFE
HxC Floppy Emulator floppy disk format, also used by Gotek drives. Version 1 only. Sectors can be written, but disks can’t be formatted.
.IMD
ImageDisk floppy disk format, from Dave Dunfield’s ImageDisk program. Common for Model II and other 8-inch disks. Sectors can be written, but disks can’t be formatted.
.HDV
A hard disk image, used by xtrs, sdltrs, and the FreHD hard drive emulator. LDOS 5, LS-DOS 6, and DOSPLUS 3 partitions are read; read-only.
.ASM
An assembly language file, generated by disassembling a .CMD, .SYS, or .3BN file using the disasm command.
.LST
An assembly language listing file, generated by the asm or disasm commands’ --listing flag.
.ROM
A raw machine language file, often used as the contents of ROM.
.BIN
A file of unknown type, but sometimes synonymous with .ROM.
.HEX
Intel HEX file, a text file for burning EPROMs. Can be generated by the assembler when developing a ROM.

Usage

The tool takes a command as its first argument:

% trs80-tool COMMAND args ...

Global flags work with every command:

--version Show the tool’s version number.
--help Show the usage message.
--color COLOR Set the color mode: off, 16, 256, 16m, or auto. The default, auto, detects the terminal’s color capabilities. Use the flag to turn color off, or to force it on when piping into another program. The tool also honors the NO_COLOR and FORCE_COLOR environment variables.
--no-pager Don’t send output to a pager (see below).
--trace MODULE Show trace logs for a module: base (TRS-80 file formats), emulator (the TRS-80 emulator itself), floppy (floppy-related messages), or z80 (the Z80 CPU emulator). These logs are mostly for the developer. Repeat the flag to trace several modules.
--log-file FILE Also write log messages to a file.
--no-pager Commands that can print a lot (dir, info, sectors, hexdump, and disasm) send their output to a pager when it’s going to the terminal. The pager is the TRS80_TOOL_PAGER environment variable if it’s set, then PAGER, then less (except on Windows, which only pages if one of the variables is set). Set it to cat or to an empty string, or use this flag, to turn paging off.

dir

The dir command shows the contents of an archive file. Archives files are those that can contain other files. These are cassette files (in WAV or CAS format), floppy disks (in JV1, JV3, DMK, DSK, SCP, HFE, or IMD format), and hard disks (in HDV format). Each hard disk partition's files are shown in a directory named for the partition, such as LDM3HDB.

% trs80-tool dir FILE
--system Show system files, which are normally hidden.
--cpm-records Show the sizes of CP/M text files in whole records, rather than up to the Ctrl-Z.
--json Print the directory in JSON format.

This command respects the LS_COLORS and EZA_COLORS environment variables.

info

The info command takes a list of filenames and displays a one-line description of the contents of the file, such as its type (system program, Basic program) and, if known, the embedded filename. For a hard disk, it also lists each partition, with its name, operating system, and number of files.

% trs80-tool info in1.cmd in2.bas in3.cas in4.wav in5.dmk
--verbose Show more information for some file types, such as a floppy’s geometry.
--json Print the info in JSON format. Combine with --verbose to include the extra information.

convert

The convert command converts a list of input files to an output file. There are several different ways to use this command.

A single file can be converted to another format:

% trs80-tool convert in.cmd out.3bn    (diskette to cassette format)
% trs80-tool convert in.bas out.asc    (de-tokenize Basic program)

Several files can be put into an archive:

% trs80-tool convert in1.bas in2.3bn in3.cmd out.wav

This creates a cassette audio file containing the three files. Note that the .CMD file will be converted to .3BN format.

Floppies, hard disks, .CAS files, and cassette audio files are expanded into the files they contain, so they can be converted to other archive formats:

% trs80-tool convert in.dmk out.wav
% trs80-tool convert in.wav out.cas

The output must be a file; to extract the contents of an archive, use extract.

--baud RATE Write cassettes at this baud rate (250, 500, or 1500). If not specified, it will be guessed, if possible, otherwise will be 500 baud (low speed).
--start ADDRESS Set the start address of a system program, or auto to guess one. For .BIN and .ROM input, this is also the load address.
--system Include system files from floppies and hard disks.
--cpm-records Keep the whole records of CP/M text files (see extract).

If a system program doesn’t have a built-in start address, the info command shows the one it guesses, which you can then set:

% trs80-tool info in.cas
in.cas: System program (VCEPRN, /17408) on a low speed cassette
% trs80-tool convert --start 17408 in.cas out.cas
Wrote out.cas: System program (VCEPRN) in low speed CAS file
% trs80-tool info out.cas
out.cas: System program (VCEPRN) on a low speed cassette

More examples:

% trs80-tool convert --baud 1500 in1.bas in2.3bn out.wav
% trs80-tool convert --start 0x1024 in.rom out.cmd

extract

The extract command writes the files inside a floppy image, hard disk image, .CAS file, or cassette audio file to a directory. The files go into the current directory unless you give --out-dir, which creates the directory if it doesn’t exist. Files already in the directory with the same names are overwritten.

% trs80-tool extract in.dmk
% trs80-tool extract in.dmk --out-dir out
% trs80-tool extract in.hdv --out-dir out
% trs80-tool extract in.cas --out-dir out
% trs80-tool extract in.wav --out-dir out

A hard disk’s files go into a subdirectory for each partition, named for the partition, as in out/LDM3HDB/BASIC.CMD.

To extract only some of the files, name them after the input file. Each name is matched against the names of the files on the disk (as dir shows them), not against files on your computer, and may have wildcards:

% trs80-tool extract in.dmk "*.bas"
% trs80-tool extract in.dmk HELLO.BAS GOODBYE.BAS --out-dir out
% trs80-tool extract in.hdv "LDM3HDB/*.CMD" --out-dir out

Quote the names that have wildcards, so that your shell doesn’t expand them against the files in the current directory first. Matching ignores case. A * matches any number of characters except /, a ? matches one character other than /, and ** matches any characters including /. Every other character matches itself. On a hard disk or Xenix floppy, whose files are in directories, a name without a / is matched against the last part of each path, so "*.CMD" finds the .CMD files in every directory; a name with a / is matched against the whole path. Elsewhere a / in the name means ., so HELLO/BAS finds HELLO.BAS. It’s an error if a name matches no files, and nothing is written.

--out-dir DIR Write the files to this directory, which is created if needed. The default is the current directory.
--system Include system files from floppies and hard disks.
--cpm-records Keep the whole records of CP/M text files, rather than stopping at the Ctrl-Z.
--ucsd-pascal-raw Write UCSD Pascal text files as they are on the disk, rather than converting them to plain text.
--lowercase Write the files with lowercase names.
--mark-damaged Add [DAMAGED] to the names of damaged files, as in HELLO.BAS [DAMAGED].
--json Print a JSON object to standard output instead of writing files. Only the files that match the names, if any, are included. The JSON includes the contents of each file in base64. This can’t be used with --out-dir.

disk

The disk command works on one floppy image: give the image, then one or more commands to run on it, separated by a lone :.

% trs80-tool disk in.dmk dir
% trs80-tool disk in.dmk extract "*.bas" --out-dir out : free
% trs80-tool disk in.dmk check

The image doesn’t have to exist: create makes a new, blank disk, and the other commands can then work on it in the same run.

% trs80-tool disk games.dmk create ldos-5.3 : add *.bas

Most commands only read the disk; add, rm, mv, attr, label, create and format change it. Commands that change the disk do so in memory, and the image is written once, after the last command, all or nothing: if any command in the chain or any line of a script fails, nothing is saved. The image is replaced in one step, so an interrupted write can’t leave half a disk.

Only some disks can be changed: floppies of the TRSDOS family whose DOS is TRSDOS 2.x, TRSDOS 1.3, LDOS 5, TRSDOS 6 / LS-DOS 6, or DOSPLUS 3, as long as check finds no problem with the file system. Every change is checked before it is kept: the tool decodes the changed disk again and refuses the change unless the layout and every other file are exactly as they were. --dos and --force below can relax the requirements on the disk when the tool is unsure.

-o FILE, --output FILE Save the changes to FILE instead of replacing the image. Put it before the first command.
--dry-run Write nothing, and say whether the disk would have changed. This overrides --output. Put it before the first command.
--dos NAME Write by the rules of this DOS, for a disk that doesn’t say which DOS wrote it or to override what it says. The names are trsdos-2, trsdos-1.3, ldos-5, trsdos-6 (also ldos-6 and ls-dos-6), and dosplus; help dos lists them. It doesn’t change how the disk is read, and it only applies to TRSDOS-family disks. It also changes what info and check say about whether the disk is writable. Put it before the first command.
--force Write even where the disk looks doubtful (a layout that had to be guessed, a damaged file system), after printing a warning. It can’t override a problem with no safe way around, such as a disk whose DOS can’t be identified, which --dos settles. Put it before the first command.
dir [NAME...] List the files, as the dir command does, or only those matching the names, which may have wildcards as in extract. System files are listed only with --system, but a name without wildcards finds a system file either way.
extract NAME... Copy files to your computer, as the top-level extract command does, with the same names, wildcards and options (--out-dir, --lowercase, --mark-damaged). A wildcard never matches a system file; to copy one, give its name. extract "*" copies them all. With --as PATH, write the one file that the name matches to that path. Also called get.
list NAME Show a file’s contents: a BASIC program as a listing, a text file as text (with your computer’s line endings), and anything else, such as a program, as an annotated hex dump. A file counts as text if it has no NUL bytes and nearly all of its bytes are printable characters or line endings; trailing Ctrl-Z and NUL padding is ignored. --hex shows a hex dump whatever the file is, and --raw writes the file’s bytes unchanged to standard output, with no pager, for piping. If the name has wildcards and matches several files, each is shown under a ==> NAME <== line. A wildcard never matches a system file, but its name does. Output goes through the pager when it’s a terminal (see --no-pager). It works on any disk we can read, including a read-only one. Also called type and cat.
add HOSTFILE...

Copy files from your computer onto the disk, converting them as needed. A .bas file of BASIC text is tokenized (Tokenized hello.bas.), or with --ascii kept as text with CR line endings (Disk BASIC loads those too); tokenized BASIC is copied as it is, and text that isn’t BASIC is an error that names the line. A .3bn system program, or a .cas that holds one, becomes a CMD program that the DOS can run, named with the extension CMD (game.3bn becomes GAME/CMD); a .cas that holds a BASIC program becomes tokenized BASIC, and one with several programs is refused (use extract on it first). The LF and CRLF line endings of .txt, .asm, .jcl, .doc, .hlp, .lst, .fix, and .src files become CR (Converted line endings of notes.txt.). Every other file is copied byte for byte, and --binary copies every file that way, with no conversion at all. (--ascii and --binary can’t be used together.) The host names may have wildcards. Each file’s TRSDOS name is made from its host name, upper-cased, with other characters dropped and the name cut to 8 letters and a 3-letter extension, and the command says when that changed it (hello-world.bas will be HELLOWOR/BAS.); --as NAME gives the name of the one host file instead. --system and --invisible set those attributes. Nothing is added unless every file can be: a name that is already on the disk (unless you give --overwrite), two files with the same TRSDOS name, or too little room is an error. A file that would need more than four fragments of free space can’t be added yet. It prints Added HELLO/BAS (1,234 bytes). for each file. Also called import and put.

--overwrite replaces the files that are already on the disk, in the same directory slot, and prints Replaced HELLO/BAS (1,234 bytes). for them. The new copy keeps the old file’s attributes, passwords, record length, and date, except that --system, --invisible, and --date change those they name (on the LDOS line the file is also marked as changed since the last backup). BOOT/SYS and DIR/SYS can’t be replaced. The new copy is written to free space first and the old copy freed afterward, so the new copy never lands on the old one’s sectors; only if it wouldn’t fit that way does it take over the old copy’s space, and the command warns when that happens. As with every change, nothing is saved unless every file can be added or replaced.

Files get no date unless you give --date YYYY-MM-DD, and only LDOS and TRSDOS 6 / LS-DOS 6 disks keep one: TRSDOS 2.x and DOSPLUS 3 disks ignore it, with a warning. Those disks hold the years 1980 to 1987, or 1980 to 2011 on an LDOS 5.3 or LS-DOS 6.3 disk (which also stores the time of day), and a year outside that is an error. With no date, the entry is marked as having none.
rm NAME... Remove files from the disk, freeing the space they used. The names may have wildcards, as in dir; every name must match a file, or nothing is removed. A wildcard never matches a system file; to remove one, give its name. BOOT/SYS and DIR/SYS can’t be removed at all. It prints Removed HELLO/BAS. for each file. Also called del, delete, kill, and remove.
mv OLDNAME NEWNAME Rename a file on the disk. Both names are single TRSDOS names, with no wildcards, and either / or . may come before the extension. The new name must not belong to another file. System files can be renamed, but BOOT/SYS and DIR/SYS can’t be. Only the name changes, not the file’s contents, dates or attributes. It prints Renamed HELLO/BAS to GREET/BAS. Also called ren, rename, and move.
attr PATTERN...

Change the attributes of files, or with no attribute options show them. The patterns may have wildcards, as in dir; every pattern must match a file, or nothing is changed. A wildcard never matches a system file; to change one, give its name. The attributes are --invisible or --visible (whether directory listings show the file), --system or --no-system (BOOT/SYS and DIR/SYS can’t change), --protect LEVEL, --password PW (the update, or owner, password, which allows full access) and --access-password PW (which allows access up to the protection level); an empty password removes the password. A password is up to 8 letters and digits, starting with a letter. --date YYYY-MM-DD or --no-date sets or removes the date, on the DOSes that store one (see add) and as an error elsewhere. It prints Changed HELLO/BAS: invisible, protection READ. for each file. Also called attrib.

The protection level is a name or a number from 0 to 7, in any case. The names are the disk’s DOS’s: FULL (0), KILL (1), RENAME (2), WRITE (4), READ (5), EXEC (6), and NO_ACCESS (7) on TRSDOS 2.x, LDOS 5, and the other DOSes of that family, but REMOVE (1), WRITE (3), and UPDATE (4) on TRSDOS 6 and LS-DOS 6. An unknown name lists the ones that fit the disk. LDOS 5.3 and LS-DOS 6.3 disks keep a time stamp where the access password would go, so they have no access password to set, and system files there have no dates.
label

Show or change the disk’s name, date, master password and AUTO command. With no options it shows them, and needs no write access: the name, the date as the disk stores it, whether the master password is PASSWORD (the usual one), blank, or something else (shown as its hash, since the password itself isn’t stored), and the AUTO command, which is the command the DOS runs when it boots. The options each change one field and leave the others alone: --name NAME (up to 8 characters, uppercased except on DOSPLUS), --date YYYY-MM-DD (the DOS keeps only two digits of the year, so the year must be one it can enter: 1980 to 1999, or to 2011 on LDOS 5.3 and LS-DOS 6.3 disks), --password PW (up to 8 letters and digits, starting with a letter; an empty one makes it blank), and --auto COMMAND or --no-auto. It prints what changed, such as Name is now GAMES. AUTO command is now BASIC RUN"MENU".

The AUTO command is up to 31 characters on TRSDOS 2.x, LDOS 5 and DOSPLUS 3, which keep it in the same sector as the name, and up to 79 on TRSDOS 6 and LS-DOS 6, which keep it in the system information sector of the boot track. A TRSDOS 6 disk that has no such sector (one that another program formatted) can’t be given an AUTO command. Changing the name or date doesn’t change the DOS release banner that TRSDOS 6 keeps in that sector.
info Describe the image and its file system, as info --verbose does, with the free space and whether the disk can be written.
free Show the space left for new files on a TRSDOS-family disk: granules that the GAT says are free and that no file uses.
check Check a TRSDOS-family file system for problems, changing nothing: files that share granules, files in granules the GAT says are free, extents past the end of the disk, HIT bytes that don’t match names, and damaged files. It also says whether the disk would be safe to write, and if not, why not.
repair [--free-unclaimed]

Fix the damage that check finds, where it can be fixed without guessing, in the GAT, the HIT and the directory only: granules that a file uses and the GAT says are free are marked used, HIT bytes that aren’t the hash of the file’s name are set to it, and extended directory entries that no file reaches are deleted. It prints what it changed, then the damage it can’t fix (files that share granules, extents past the end of the disk, damaged files), and says whether the disk is now safe to write. It works on a disk that is damaged but otherwise sound, which is the only kind of write that such a disk allows, so repair : add FILE works. It refuses a disk that can’t be written for another reason, such as an uncertain layout, even with --force. Under TRSDOS 2.x’s rules the HIT bytes of extended directory entries are left alone, since we don’t know what the DOS puts there.

Granules that the GAT marks used but no file claims are left alone, since some programs keep data there; --free-unclaimed frees them. Granules on the boot cylinder and locked-out ones are never freed. Like any other change, a repair can be taken back with undo.
create DOS

Make a new, blank, formatted data disk, with no files, the way the DOS’s own FORMAT leaves one (or, with --system, a bootable system disk). It works when the image doesn’t exist yet (the disk is saved under that name at the end), or with --force to replace in memory the disk that the image has. The image is always a DMK one, so a name ending in .jv1, .jv3, .dsk, .hfe or .imd is refused. The disk can be used by later commands in the same run, and a quit or the end of the run saves it.

The DOS to make the disk for is required, and comes first. It is one of trsdos-2.3, trsdos-1.3, ldos-5.3, trsdos-6.2 and lsdos-6.3; help create, and the error for a missing or unknown DOS, list them with what each makes. (This is not the --dos option that goes before the first command.) The options are --cylinders N (default 40, or 35 for TRSDOS 2.3; the DOS sets the limits), --sides 1|2 (default 1; TRSDOS 2.3 and 1.3 have only one), --density single|double (default: single for TRSDOS 2.3, double for the others), --model 1|3|4 (only chooses LDOS 5.3’s default density: single for the Model I, double otherwise), --name NAME (default DATADISK) and --date YYYY-MM-DD (default today, as FORMAT does).

The disk gets the DOS’s own data-disk boot sectors, copied from disks that the DOS formatted, so apart from the name and date it is the same as what FORMAT makes. It is still a data disk, not a system disk. (Where we haven’t measured the DOS’s own, which is single-density TRSDOS 6 and LS-DOS 6 disks, the disk gets a boot sector of our own that only prints a message and halts; the DOS and this tool still recognize the disk by its other sectors.)

With --system, create instead makes a bootable system disk: a copy of the DOS’s own system disk, with all its files. Each DOS has one disk (LDOS 5.3 has one for the Model I and one for the Model III, and --model 1 chooses the first), which fixes the shape of the disk, so --cylinders, --sides and --density are refused if they differ from it. --name and --date change the copy’s name and date. --minimal removes every file that isn’t a system file, keeping what the DOS needs to boot (and saying what it removed), to leave room on the disk. The result can be changed by later commands in the same run, such as add, like any other disk.

The bundled system disks, which help create also lists, are:

  • TRSDOS 2.3 for the Model I
  • TRSDOS 1.3 for the Model III
  • LDOS 5.3.1 for the Model I
  • LDOS 5.3.1 for the Model III
  • TRSDOS 6.2.1 for the Model 4
  • LS-DOS 6.3.1 for the Model 4

These disks and the DOSes’ boot sectors are the DOS publishers’ software, shipped inside the tool as the trs80gp emulator ships them. They will be taken out of the tool if the rights holders ask.
format [DOS]

Erase the disk and format it as an empty data disk. It takes the same options as create, with an optional DOS that defaults to the disk’s own (it is required if that isn’t one of the five), the cylinders and sides default to the disk’s, and an LDOS-family disk keeps its density. If the disk has files, format says how many would be lost and needs --force. The result is a DMK image, so for an image of another kind give -o NEW.dmk to save it under a new name. Like everything else it changes the disk in memory, and nothing is saved until the end.
trim

Drop tracks that the disk doesn’t use from the image, which wastes space and confuses other tools: an 80-cylinder image of a 40-cylinder disk, or a blank second side. It works on DMK, JV1 and JV3 images, rebuilding the image without those tracks, and checks that the result decodes as the same file system with every file reading the same; if not, nothing changes. With no options it drops the cylinders past the ones the file system uses (the ones that the GAT marks as beyond the disk’s end), and any cylinders at the end with no readable sectors, and says what it dropped. Some DOSes, such as TRSDOS 1.3, don’t mark their end, so only the unreadable cylinders go. If there’s nothing to drop it says so and changes nothing.

--cylinders N keeps cylinders 0 to N-1. It refuses if a file or the directory has data on a dropped cylinder (naming them and the cylinders the file system covers), or if the dropped cylinders are free space that the file system expects to have, unless you give --force. On a disk with no file system, it refuses if a dropped track holds data that isn’t filler (each sector the same byte, or the same two bytes alternating), unless --force.

--side 0 drops side 1. It refuses if the file system allocates on both sides, or, with no file system, if side 1 holds data that isn’t filler (unless --force). A single-sided image has nothing to drop. --force also lets trim work on an image marked write-protected.

Like everything else, trim changes the disk in memory and nothing is saved until the end, so --dry-run and -o work.
boot [--model 1|3|4] [--write-protected]

Boot the disk, as it is in memory, in the emulator, drawn in the terminal the way run draws it. Ctrl-C stops the emulator and returns to the prompt (or to the next command in a chain). It says which model it chose and why: a Model I for TRSDOS 2.x and for other DOSes on single-density disks, a Model III for TRSDOS 1.3 and for other DOSes on double-density disks, and a Model 4 for TRSDOS 6 and LS-DOS 6; a disk with no DOS we recognize gets a Model III. --model overrides this. Also called run.

The DOS can write to the disk, but only in memory: the whole session is one change that undo takes back, and save or quit saves, so the image file is not touched until then. --write-protected mounts the disk write-protected, and a disk whose image is marked write-protected stays so. Afterward the file system is read again, since the DOS may have changed anything. It needs a terminal, and refuses to run in a script.
undo

Take back the most recent change to the disk (an add, rm, label, create, format, trim and so on), restoring the disk exactly as it was, including its image format, and say which command it undid. It can be repeated to go further back, up to the last 100 changes. If undoing takes the disk back to what was last saved then there are no changes to save. It says so if there’s nothing to undo. It works in a chain too: rm HELLO.BAS : undo.
redo Do again the change that undo took back. Making a new change after an undo forgets what could have been redone.
revert Go back to the disk as it was when last saved (or as it was opened, if it hasn’t been saved), in one step. It counts as a change, so undo takes the revert back.
save Save the changes now and carry on. Useful in the prompt; it says so if there’s nothing to save.
quit Save the changes, if any, and leave the prompt. Also called exit; Ctrl-D does the same.
abort Leave the prompt, discarding any changes. Ctrl-C at an empty prompt does the same; with text on the line, Ctrl-C only clears the line and shows a new prompt.
help [COMMAND] List the commands, or describe one with its options and other names (ls for dir, for example).

With no commands after the image, disk opens a prompt where you type the same commands, one line at a time, with tab completion of command and file names. quit saves any changes to the disk and leaves it. If the input isn’t a terminal, the commands are read from it instead, so trs80-tool disk in.dmk < script.txt runs a script, stopping at the first error. Lines starting with # are comments.

% trs80-tool disk in.dmk
in.dmk: Floppy disk (DMK), LDOS 5.1, 26 files, 157 KB free
Type "help" for a list of commands, and "quit" to leave.
>free
157 KB free (105 granules of 1,536 bytes each)
>quit

Flags such as --color go before disk; after the image, everything belongs to the disk commands.

hexdump

The hexdump command displays a hex dump of the input file, with annotations.

% trs80-tool hexdump in.cmd
--no-collapse Show every line, rather than collapsing identical ones.

sectors

The sectors command displays a table of the sectors in a floppy disk. The columns are the sectors and the rows are the tracks. For each sector a character is displayed:

- No sector.
S Single-density sector.
D Double-density sector.
X Deleted sector.
C CRC error (ID or data).
? Missing sector.
--contents Also show the contents of the sectors.
--bad Instead of the table, list the sectors that are missing or that have a CRC error, and which file (if any) is on each one. Floppies without bad sectors are left out.
--json Print the sector information in JSON format, with a description of each sector instead of the table. Combine with --contents to include each sector’s data in base64, and with --bad to include only the bad sectors.

asm

The asm command assembles the specified assembly language source code:

% trs80-tool asm program.asm program.cmd
% trs80-tool asm --baud 1500 program.asm program.cas
% trs80-tool asm --listing program.lst program.asm program.cmd

It can generate .CMD, .3BN, .CAS, .WAV, BIN, or HEX files.

--baud RATE The baud rate for .CAS and .WAV files: 250, 500 (the default), or 1500.
--listing FILE Also write a listing file.
--model MODEL The target model: 1, 3 (the default), or 4.

The assembler defines the constants __MODEL__ (the number of the target model) and __MODEL_1__, __MODEL_3__, and __MODEL_4__, which can be used with if, else, and endif to write code that differs between models:

	if __MODEL__ == __MODEL_1__
	ld a,(0x37E0)
	else
	in a,(0xEC)
	endif

disasm

The disasm command disassembles the specified program:

% trs80-tool disasm saucer.cmd
% trs80-tool disasm --org 0x8000 file.bin
% trs80-tool disasm --entry 0x0000,0x3799,0x377B model3.rom
% trs80-tool disasm --listing program.cmd

If the program is a .CMD, .SYS, or .3BN file, it is loaded into the correct place in memory. If it’s a .ROM or .BIN file, it is loaded at 0x0000.

The disassembler tries to guess which bytes are code and which are data by following the path of the program, starting with its main entry point.

--org ADDRESS Load a .ROM or .BIN file at this address rather than 0x0000.
--entry ADDRESSES Add entry points (comma-separated).
--full Disassemble straight through the program rather than following its path, so bytes that are data are disassembled too.
--data-comment Comment each instruction with the ASCII of its bytes, to make data easier to find with --full.
--no-labels Don’t create labels for jump targets.
--no-known Don’t refer to known ROM addresses by name.
--hex-format FORMAT The format of hex numbers: c for 0x12 (the default), dollar for $12, or h for 12h.
--upper Write assembly language in upper case.
--listing Write a listing instead of assembly language.
--no-binary Leave the opcode bytes out of the listing.

run

Run a TRS-80 emulator in the shell. This is experimental and does not currently work well with games, and may not work at all in a Microsoft Windows shell. Specify a program or floppy to load and run directly:

% trs80-tool run
% trs80-tool run tdos13a.dsk
% trs80-tool run frogger.cmd
% trs80-tool run --model 1 --level 1
% trs80-tool run --mount in.cas in1.dmk in2.dmk in3.dmk

Floppies, including one given as the program to run, are write-protected unless you specify --writable.

--model MODEL The model: 1, 3 (the default), or 4.
--level LEVEL The Basic level: 1 or 2 (the default).
--mount FILES... Mount a cassette and floppies. Only one cassette may be mounted, but several floppies can be mounted.
--writable Let the emulator write to floppies, and save the changes to their files. A floppy stays write-protected, with a warning, if its file is read-only or its image (DMK, JV3, or HFE) is marked write-protected.
--printer FILE Write printer output to a file, rather than showing it below the screen.
--xray Show nothing in the shell, but start a web server for the X-ray debugger. This is experimental and not yet documented.

repl

Starts an interactive session for exploring the Z80. Type help to get a list of commands. Type an assembly language instruction (such as ld a,5) to assemble it, write it to memory, explain it, execute it, and show its effects on flags and registers. This virtual machine is not in a TRS-80 context (it has no ROM or peripherals).

mcp

Runs an MCP server on stdin/stdout, which lets an AI assistant drive a TRS-80 directly. The assistant can boot a ROM, type at it, run it for an exact number of clock cycles, and inspect the screen, memory, and registers. The machine stays running between requests, so the assistant can explore interactively instead of guessing.

You don’t run this command yourself. Your AI tool starts it for you, so what you do is tell that tool about it. With Claude Code:

% claude mcp add --scope user trs80 -- trs80-tool mcp

Other MCP clients use a JSON configuration file. The entry looks like this:

{
    "mcpServers": {
        "trs80": {
            "command": "trs80-tool",
            "args": ["mcp"]
        }
    }
}

In both cases trs80-tool must be on your PATH. If it isn’t, use the full path to the binary instead. MCP servers are started when your AI tool starts, so restart it after adding this.

These are the tools the assistant gets:

  • boot — start a machine, either with the stock Basic ROM or with a .cmd file that replaces the ROM. On the stock ROM it answers the Memory Size? question, and Cass? too on the Model III and 4 (the Model I doesn’t ask it), and waits for READY.
  • load_program — load and start a program file on the running machine.
  • mount_disk — put a floppy disk image in a numbered drive, without rebooting, for programs that need more than one disk.
  • reset — reset the machine, keeping the disks mounted, which is how you boot from a disk you just mounted.
  • load_basic — put a Basic listing straight into memory on the stock ROM, much faster than typing it.
  • type — type text at the keyboard, waiting until the ROM or DOS has taken every key.
  • key — press or release a single key and leave it that way, for programs that care whether a key is held down.
  • run — run for a number of clock cycles or emulated seconds.
  • step — single-step the CPU.
  • run_until_pc — run until the program counter reaches an address.
  • run_until_screen — run until some text appears on the screen, and report roughly how long it took.
  • run_until_memory — run until a memory location holds a value, and report exactly how long it took. This is how you time a program precisely, for example by waiting for the first and last bytes of a screen fill.
  • screen — read the screen as text.
  • read_memory, write_memory, registers.
  • search_memory — find a byte sequence, for locating code in ROM.
  • disassemble — disassemble straight out of memory, ROM included.
  • profile_pc — run for a while and report where the program counter spent its time, as a histogram of the hottest addresses.
  • call_routine — call a machine-language routine with chosen registers and report exactly how many clock cycles it took, the way another program calling it would see it.
  • screenshot — write the screen to a PNG.
  • record_start and record_stop — record an MP4 of everything the machine does in between. Frames are taken at a fixed interval of emulated time, so the video plays back at true speed and shows honestly how fast a program is. Needs ffmpeg on your PATH.

Timings are reported in Z80 clock cycles (t-states) rather than wall-clock time, so they’re exact and repeatable no matter how fast the emulator happens to run on your machine.

help

The help command shows more specific information about other commands:

% trs80-tool help dir
% trs80-tool help convert

Limitations

  • The tool reads floppy disks and hard disks. The only change it can make is removing files from a floppy with disk rm, and only on the TRSDOS-family DOSes listed there.
  • Hard disks can’t be mounted in the emulator (run and mcp), and the sectors command shows only floppies.
  • On hard disks, only LDOS 5, LS-DOS 6, and DOSPLUS 3 partitions are read.
